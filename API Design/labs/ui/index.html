What an API actually is

An API is a promise about behaviour across a boundary. One side agrees to accept certain messages and to answer in a certain shape; the other side agrees to ask only in that vocabulary. Everything below the promise — the language, the database, the deploy schedule — stays private and swappable.

Interface, not implementation

The client never learns whether the data came from Postgres, a cache, or a spreadsheet. That ignorance is the product.

A contract, not a suggestion

Once someone builds on your response shape, changing it breaks them. This is why API design is more like publishing than coding.

A boundary you can price

Round trips, payload bytes, and failure modes all live at this boundary — so design decisions here show up directly in latency and cost.

Lab 1 · REST over HTTP

REST models the world as resources with addresses. HTTP already knows how to fetch, cache, retry and version addressable things — REST's whole bet is to reuse that instead of inventing it. Source: labs/rest/api.js.

Nouns in the URL, verbs in the method

GET /artists/a1, never /getArtist?id=a1. The method already says what you are doing, and infrastructure understands it.

Status codes are the API

201+Location, 204, 304, 404, 422, 409. A 200 carrying {"status":"error"} throws away everything the network knows how to do for you.

The N+1 tax

Resource granularity is a trade: small resources cache beautifully and cost round trips. Watch the call count on the Compare tab.

Lab 2 · GraphQL

One endpoint, one type graph, and the client declares the response shape. You buy the end of over-fetching and round-trip waterfalls; you pay in caching, cost control and observability. Source: labs/graphql/schema.js.

Always 200

Failures come back inside errors alongside partial data. Your monitoring must learn to read bodies, not status codes.

One URL kills HTTP caching

No per-resource ETags. You replace them with persisted queries, CDN tricks and client-side normalised caches.

Flexibility is an attack surface

Depth limits, cost analysis and allow-lists are not optional extras — try the "deep query" preset and watch it get rejected.

Lab 3 · gRPC

Not resources and not queries — typed function calls defined in a .proto file, serialised as binary protobuf over HTTP/2. Fast, strict, streaming-native, and invisible to your browser without a gateway. Source: labs/grpc/catalog.proto.

The contract is compiled

Both sides generate code from the same .proto. A field mismatch is a build error, not a 3 a.m. page.

Field numbers, not names

Tags 1,2,3… are the wire format. Renaming a field is free; reusing a retired tag number silently corrupts data.

Browsers cannot speak it
